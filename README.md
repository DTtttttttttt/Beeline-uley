# Планировщик выездов инженеров

Кейс «Билайн Бизнес», ЛЦТ 2026. Панель диспетчера, которая распределяет заявки по бригадам на один день, строит маршруты, показывает их на карте, объясняет решения и перестраивает план по событиям в течение дня.

## Запуск

Нужны Docker с Docker Compose (память Docker — около 8 ГБ), около 3 ГБ на диске и ключ 2ГИС
(подойдёт бесплатный демо-ключ). Valhalla обязательна: она считает время в пути и рисует маршруты
по дорогам. Её тайлы собираются один раз, это около 20 минут.

```bash
cp .env.example .env
# вписать ключ 2ГИС в DGIS_API_KEY

# 1. Дороги: выгрузка OpenStreetMap, из неё вырезаются Москва и область
curl -L -o cfd.osm.pbf https://download.geofabrik.de/russia/central-fed-district-latest.osm.pbf
MSYS_NO_PATHCONV=1 docker run --rm -v "$PWD:/data" debian:12-slim sh -c "apt-get update -qq && apt-get install -y -qq osmium-tool && osmium extract -b 35.1,54.2,40.3,57.0 /data/cfd.osm.pbf -o /data/valhalla/custom_files/moscow-region.osm.pbf"
rm cfd.osm.pbf

# 2. Тайлы Valhalla: ждём, пока сервер ответит
cp valhalla/custom_files/valhalla.json valhalla.json.bak
docker compose --profile valhalla up -d valhalla
until curl -sf http://localhost:8002/status > /dev/null; do sleep 30; done
mv -f valhalla.json.bak valhalla/custom_files/valhalla.json
docker compose --profile valhalla restart valhalla

# 3. Остальные сервисы
docker compose --profile valhalla up -d --build
curl http://localhost:8000/api/health   # mongo и valhalla должны быть "ok"
```

Когда всё поднялось, откройте `http://localhost:3000`. При первом входе откроется окно «Новый
датасет». Выберите в нём заявки и состав бригад и нажмите «Загрузить и рассчитать». Варианты
считаются около 40 секунд. Затем выберите нужный вариант кнопкой «Выбрать». После открытия первого
рассчитанного плана короткий тур покажет основные элементы интерфейса; его можно пройти или
пропустить.

Остановить: `docker compose --profile valhalla down`. Следующий запуск — `docker compose --profile
valhalla up -d`, тайлы собирать заново не нужно.

## Что умеет

- **Два плана на одних данных:** базовый, строго по алгоритму ТЗ, и оптимизированный (Google OR-Tools).
  Оптимизация учитывает, что авария важнее любой другой заявки, затем стремится выполнить больше заявок,
  задействовать меньше бригад и проехать меньше километров. Базовый план выдаётся только если он не хуже.
- **Ограничения:** навык, транспорт, оборудование и инструменты, окно заявки, смена бригады, время
  в пути, количество оборудования, которое бригада может взять с собой на день. Каждый план заново
  пересчитывается отдельной независимой проверкой.
- **Объяснения:** почему заявка досталась этой бригаде и почему не подошли остальные, почему маршрут
  именно такой, а для неназначенной заявки — причина и пометка «перенести на следующий день».
- **События в течение дня:** новая или срочная заявка, авария, недоступность бригады, выход новой
  бригады, отмена, перенос, правка заявки или бригады, фиксация факта выполнения. Уже начатая работа не
  пересматривается. Отмену и перенос можно применить сразу к нескольким заявкам. Видно, что изменилось
  и каким клиентам нужно сообщить новое время.
- **Ассистент:** фраза обычным текстом («Соколов заболел с 13:00», «перенеси заявку 74198 на завтра»,
  «отмени все заявки в Кашире», «новая авария на Волгоградском 128 к5») или вопрос («почему заявка
  74198 не у Соколова?», «кто свободен?»). Умеет одним предложением отменить или перенести несколько
  заявок — по номерам, инженеру или населённому пункту, не затрагивая уже начатые и закрытые, — и по
  просьбе пересчитать весь день с начала. Помнит контекст диалога и уточнения; «Новый чат» очищает
  переписку. Новую заявку вне Москвы и Московской области не предлагает.

  Фразу разбирает YandexGPT, но ничего не решает: событие или заявка остаются предложением, которое
  применяет диспетчер, а ограничения по-прежнему проверяет расчёт. Кнопка ассистента находится на
  карте. Нужны `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` в `.env` (см. `.env.example`), без них кнопки нет.
  Там же можно настроить модель, тайм-аут, лимит ответа и глубину рассуждений. Адреса заявок при этом
  уходят в Yandex Cloud.
- **Интерфейс:** отдельные сценарии знакомства для компьютера и телефона, адаптивная карта и списки,
  а для долгих операций — полоса прогресса с оценкой оставшегося времени. Формы заранее проверяют
  обязательные поля, координаты, смены и окна заявок и подсвечивают поля, которые нужно исправить;
  повторные действия на время расчёта блокируются.
- **Сверх обязательного:** сравнение шести вариантов расчёта, метрики и графики, ручное переназначение
  с проверкой ограничений, прогноз вероятности опоздания, перемотка дня назад, готовые демо-наборы
  (три участка × три состава бригад), загрузка своего набора в JSON или CSV.

## Как устроено

| Часть | Технологии |
|---|---|
| `backend/` | Python 3.12, FastAPI, Google OR-Tools, MongoDB |
| `web/` | Nuxt 4 (Vue 3), карта 2ГИС MapGL |
| расстояния и время в пути | собственный Valhalla на данных OpenStreetMap |
| адреса → координаты | 2ГИС Geocoder |
| `data/` | встроенный набор, примеры для загрузки, сценарии, готовые таблицы переездов |
